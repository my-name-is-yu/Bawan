# 短い英日翻訳の比較と採用結果

2026-11-13。EN→JPの1〜5語を対象に、PLaMoの16候補とApple標準翻訳の2方式を比較した。
採用したのは、**1語では入力言語を英語と明示し、2〜5語では「英語から日本語への翻訳です。」という短い文脈を加える**方式。
6語以上、逆方向、対応外の文字を含む入力は従来のプロンプトを使う。

モデル、コンテキスト長8192、greedy生成、KVリセット、ストリーミングとキャンセルは維持する。
macOS 14対応の変更、追加モデル、辞書、Swiftブリッジ、常駐監視、設定項目は製品に追加していない。
Appleの評価用ホストと記録用ツールは製品ビルドに含まれない。

## 方法と結果

保存済みの公式PLaMo 3 Translate 0.8B Q4_K_M、llama.cpp b12307を使用。
モデルSHA-256は`70891ec70dc7ab4205745a38307867c2881b99239f20327927633abfe4bc9ec6`。
Apple M4・16GB・macOS 26.6.2で実行した。

選定用60件・未見確認用60件は、それぞれ単語・熟語・短文を20件ずつ含む。
別に長文・逆方向・固有名詞等の対照24件を用意した。
出力を重複排除し、候補名を隠してAIが意味と自然さを0〜2点で評価した。
2は意味が正しく実用的、1は部分的、0は明確な誤訳・未翻訳。妥当な多義、定着した外来語や固有名詞を許容した。
**少数例のAI評価であり、人の採点や標準ベンチマークではない。**

| 評価群 | 現状の正解 | 採用候補の正解 | 現状の誤訳 | 採用候補の誤訳 |
| --- | ---: | ---: | ---: | ---: |
| 選定用60件 | 53 | 57 | 3 | 1 |
| 未見確認用60件 | 54 | 57 | 4 | 3 |
| 対照24件 | 23 | 23 | 0 | 0 |

選定は総合点116/120で同率だった候補から行った。
例示を加える候補より負荷が小さく、`serendipitous`を無関係な「世俗的な」に変えなかったことを考慮した。
選定記録を保存してから、未見出力を生成した。未見確認後のプロンプト調整は行っていない。

事前の採用条件「未見で正解が3件以上増える・誤訳数が増えない・正解から誤訳への悪化がない・各分類と対照群の総合点が下がらない」はすべて満たした。
未見の改善例は`lose track`の「道に迷う」→「見失う」、`bring up`の「引き上げる」→「取り上げる」、`You're welcome to join.`の「どういたしまして。」→「ぜひご参加ください。」。

前回の78件すべてを取得できなかったため、今回の未見入力が過去の全実験から独立しているとは断定しない。
既知の例と翻訳例に重なる項目を除き、今回の候補選定には未見出力を使用していない。
語句の曖昧な採点については、独立評価と判断の記録も保存した。

## Apple標準機能

OS公式の同意画面から英日言語データを導入し、`installed`を確認してから
`lowLatency`と`highFidelity`を各60件で比較した。
両方式の出力は全件同一で、正解53・部分3・誤訳4、総合点109/120だった。
`break a leg`が「足を壊す」、`hit the sack`が「くたたき」、`put off`が「出航する」となる例があり、今回は採用しなかった。
`highFidelity`指定はApple Intelligenceの実利用を証明しない。利用できない場合の通常モデルへのフォールバックがある。[Apple公式仕様](https://developer.apple.com/documentation/translation/translationsession/init(installedsource:target:preferredstrategy:))

標準辞書は親単語の長い説明を返す場合があり、短文の言語判定にも誤認があったため、直接の訳語供給や翻訳方向の置換には使っていない。

## 速度・メモリ

PLaMoは候補を入力ごとに切り替え、各300件で温間性能を比較した。
初回は別プロセスで3回ずつ測った。p95はnearest-rank。

| 指標 | 現状 | 採用候補 | 増分 |
| --- | ---: | ---: | ---: |
| 温間完了p95 | 53.949ms | 54.420ms | +0.471ms |
| 初回要求の中央値 | 63.182ms | 62.912ms | −0.270ms |
| 定常エンジンphysical footprintの中央値 | 220.38MiB | 220.38MiB | 0MiB |

事前の上限は温間p95+300ms、初回+2秒、定常メモリ+256MiB。
UIコードは変更せず、本番と同じエンジン・モデルを使用した。RSSとphysical footprintは別々に記録し、加算していない。
要求完了時のメモリ観測を、推論中のピークとは扱わない。

AppleもPLaMoを常駐させた状態で各300件を逐次実行した。
温間p95はlowLatency 24.37ms、highFidelity 38.58ms、ホストの新規physical footprintピークは約5.85/6.14MB。
`translationd`等は別に観測したが、`modelmanagerd`はEPERMで取得できなかったため、OS全体の増分は断定できない。
OSモデルは既にwarmであり、「初回」は新しい評価ホストでの最初の要求を指す。
Appleは品質の段階で不採用であり、これらをメモリ採用条件の達成証明には使っていない。

## 残る制限と検証

- `serendipitous`は「セランディピトゥス」という音写が残る。
- `in hot water`、`iron out`、`sleep on it`には誤訳が残る。
- `the last straw`の「最後の一滴」は意味が不完全。
- **`off the hook`は「オフ・ザ・フック」（部分）から英語のまま（誤訳）へ悪化した。** 既知の残課題として保存し、未見出力に合わせた個別例外は追加していない。
- 対照の長文1件は`application`を「申請」と訳す部分的な問題が残った。採用前後で同じ出力だった。

39件の語数境界、縮約・ハイフン・Unicode句読点・対応外文字・逆方向・通常プロンプト保持を確認した。
CTest 7/7、本番ビルド・署名、実モデルの短語・熟語・語数境界・KVリセット・入力上限・ストリーミング・キャンセルが成功。
本番エンジンで全144件を再実行し、固定した比較候補とすべて同じ出力になった。
実アプリの入力欄から`ephemeral → 儚い`、`on the fence → どっちつかず`、⇄による逆方向の翻訳を確認した。
インストール済みアプリは差し替えていない。
